# Copy / writing slop

Read this when writing UI strings, empty/error states, README or docs
in this patch. Core rules in `SKILL.md` still apply. Skip this file
when the patch adds no user-visible string. This is the fingerprint
so the agent does not ship the training-set paragraph next to the
code. Fix how it is built, not just "delve."

## What to write

Name the thing. Lead with the verb. One fact, then stop. Buttons
say the action ("Save invoice", not "Submit" / "OK" / "Get Started").
Errors name what failed and what to do. Empty states invite one
next step. Field errors: no "please", "sorry", "invalid", or
"this field is required". "Enter an email" / "Email must include
an @". Match the label wording. Service failure is a page, not a
red border. Labels stay visible; placeholders are format examples
only (`e.g. +1 415…`), never the label.

Match the product's existing voice if there is one. Do not invent
first-person anecdotes. Do not pad a README with a landscape opener.
Do not add `SUMMARY.md` / `CHANGES.md` / `IMPLEMENTATION.md` the
user did not ask for — that is agent leftover, not documentation.

## Voice and evidence

Preserve the author's nouns, point of view, contractions, and useful
uneven rhythm. Do not flatten a voice into median blog prose, or add
fake informality to make it sound human. No sample voice → stay plain
and specific; do not invent a persona.

Specific names, numbers, dates, URLs, and examples beat atmosphere.
Never fabricate them. "Research shows" needs a named source, date,
and link; an unsourced statistic is not a fact. Judge wording by its
claim and fit, not by whether a detector labels it human or AI.

One content pass, one slop pass. A second "humanizer" that swaps one
set of stock phrases for another is still slop. Keep a precise word
when it is the precise word; this list is a fingerprint, not a ban on
every individual occurrence.

## Structure tells (stronger than vocabulary)

- **"It's not X, it's Y."** / "Not just a tool, a game-changer."
  State Y.
- **Every paragraph ends in a moral.** "And so, X matters." Cut the
  takeaway; end on the last fact.
- **Hollow transitions.** Sentence-initial Moreover / Furthermore /
  Additionally / Ultimately / In conclusion. Use a period.
- **False balance.** "While it offers benefits, it also presents
  challenges." If you have a position, take it.
- **Hedge stacks.** "It may be possible that, in some cases…" Pick
  one hedge or none.
- **False frame.** "Why is X better than Y?" is not proof that X is.
  Sentence one agrees or disagrees with the premise — do not argue
  inside their setup.
- **Rule of three as filler.** "Fast, reliable, and scalable" → the
  one that is true.
- **Suspicious symmetry.** Every section the same length, same
  three-bullet shape. Title Case headings (`Impact of Technology`)
  when the file uses sentence case.
- **Over-bold.** Every instance of a chosen word, random mid-sentence
  bold, Unicode fake-bold. Distinct from a `**Term:**` restatement
  list (also slop).
- **Chat residue.** "Certainly!", "Great question!", "I hope this
  helps!", "Let me know if you want more.", "Here's a comprehensive
  overview", "In this section we will discuss", letter voice, HTML
  comments left for "the next editor." Prompt debris: `[Insert
  statistic]`, `[Your Name]`, `turn0search0`, `oaicite`,
  `contentReference[oaicite:0]`, Gemini `[cite: 1]`, `【`, `[^1]`,
  `utm_source=chatgpt.com`, `<!-- Generated by`, `As an AI language model`.
- **Significance inflation.** Pivotal moment, broader trends,
  testament to, evolving landscape — for a routine change. Tailing
  participles: "…highlighting its significance."
- **Unnamed or wrong authority.** "Experts believe" with no name; a
  real outlet attached to a claim it didn't make.
- **Knowledge-cutoff theater.** "As of my last update," "not widely
  documented," then a guess as fact.
- **Docs stencil.** "Key Takeaways," mermaid/flowchart dumps,
  "Challenges and Future Outlook," empty parent heading that only
  contains children, `---` between every section. Recap the user's
  ask in the README first paragraph. Diagram only when asked.

## Vocabulary (cluster, not find-and-replace)

One of these in a tight technical note is fine. A paragraph of them
is slop.

delve, tapestry, landscape (abstract), testament, underscore,
pivotal, intricate, meticulous, interplay, vibrant, leverage
(as verb), utilize, robust/seamless/transformative as a bundle,
holistic, synergy, paradigm, unpack, deep dive, game-changer,
cutting-edge, foster, bolster, garner, showcase, streamline,
empower, supercharge, world-class, enterprise-grade, in today's
fast-paced…, at its core, it is important to note, unlock the
power of, navigate the landscape, quietly building, this matters
because.

Em-dash asides (`—`) as the default clause-joiner are a current
fingerprint. Prefer period or comma in UI copy and README prose.
Inline `·` (`THIS MAC · 3.9 MB`, `Open source · MIT · Fast`) is a
separator tell: comma or a list. A mark on a control is a kit icon
or inline SVG; the verb has no glyph. ChatGPT/DeepSeek
often paste curly quotes (`“ ”`); match the file (usually straight).
Don't default-rewrite the user's post with "Enhance with AI."

## UX writing slop (product UI)

- Placeholder-as-label (disappears on type; often `text-gray-400`)
- "Click here" / "Learn more" / "Read more" with no destination
- Japanese-style redundancy: label, heading, and helper all say
  the same sentence three times
- Toast that restates the button ("Successfully saved
  successfully")
- Error that apologizes and names nothing ("Oops, something went
  wrong")
- Empty state that is a sad illustration and no action
- Helper text that sells ("Unlock insights") instead of format
  ("Use the workspace slug, like `acme-prod`")

Look up how this product already phrases the same moment. Then
write that short.

- `…` not `...`. Loading/saving copy ends with `…` (`Saving…`).
- Same verb through the flow: the button that says Publish toasts
  Published, not Success.
- Numerals for counts (`8 invoices`, not "eight").
- Placeholders are examples and end with `…` (`e.g. +1 415…`).
- Active voice on actions (`Save invoice`, not "Invoice will be saved").
- Match the file's heading case. Do not mix Title Case and sentence
  case on the same surface because a guideline said Chicago.

Caveman / terse agent chat is not UI copy. Buttons stay grammatical.
This file is strings next to the code, not long-form prose polish.

If the product localizes, one string with placeholders — never
`"You have " + count + " items"`. Plurals go through the i18n API.
Don't nail a button to the English width.
