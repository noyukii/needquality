# Accessibility

Read this when they said a11y, accessibility, WCAG, or keyboard
navigation. Audit the named surface; do not redesign the product.

1. Inspect native semantics, labels, heading order, focus order,
   keyboard operation, error announcements, contrast, target size,
   zoom/reflow, and reduced motion.
2. Use the repo's axe, Lighthouse, Playwright, or screen-reader check
   if present. Do not add a package for one audit.
3. Fix the smallest failing slice. Re-run the same check and exercise
   the keyboard path. Report the WCAG criterion or manual edge that
   remains unverified.

Don't: add `aria-*` to compensate for a `div` that should be a button,
claim conformance from a screenshot, or hide a failure with `eslint`
comments.
